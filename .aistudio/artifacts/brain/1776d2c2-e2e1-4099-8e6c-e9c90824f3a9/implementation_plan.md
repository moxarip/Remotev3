# Project: Remote / Clouvea — التقرير التحليلي ومعمارية نظام إدارة الأجهزة عن بُعد

> **وثيقة معمارية وخطة تنفيذ استراتيجية**  
> تحويل مشروع KDE Connect إلى نظام **Clouvea** لإدارة الأجهزة الشخصية عن بُعد (Clouvea Controller & Clouvea Node).

---

## 1. ملخص المعمارية ومفهوم النظام (System Concept & Roles)

يهدف مشروع **Clouvea** إلى بناء نظام إدارة موثوق للأجهزة الشخصية عن بُعد يعمل بنموذج **التحكم والخدمة غير المتماثل (Master-Worker / Controller-Node)**، بحيث يتصل هاتفان أو أكثر بحساب المستخدم المعتمد:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        CLOUVEA SYSTEM TOPOLOGY                         │
└────────────────────────────────────────────────────────────────────────┘

    [ Clouvea Controller ]                     [ Clouvea Node ]
    (هاتف التحكم والإدارة)                      (الهاتف المُدار ومصدر البيانات)
   ┌───────────────────────┐                  ┌────────────────────────┐
   │ • Device Fleet Dash   │                  │ • Node Identity & Auth │
   │ • Remote File Browser │                  │ • SAF Scoped Folders   │
   │ • Task Dispatcher     │                  │ • Task Runner Engine   │
   │ • Backup Manager      │                  │ • Resumable Chunk Svc  │
   │ • Telemetry Monitor   │                  │ • Background Daemon    │
   └───────────┬───────────┘                  └───────────┬────────────┘
               │                                          │
               ▼                                          ▼
   ┌───────────────────────────────────────────────────────────────────┐
   │                     HYBRID CONNECTIVITY MESH                      │
   │  Local: Wi-Fi P2P / Hotspot TLS Socket (Port 1716 UDP/TCP)        │
   │  Internet: Secure WebSocket / WebRTC Signaling Relay Server      │
   └───────────────────────────────────────────────────────────────────┘
```

### أ. دور Clouvea Controller (جهاز التحكم)
- **إدارة أسطول الأجهزة:** عرض جميع الأجهزة المسجلة، عنوان IP، نوع الشبكة (Wi-Fi/5G)، مستوى البطارية، مساحة التخزين المتوفرة، وحالة الاتصال.
- **إصدار المهام والطلبات:** إرسال أوامر تشغيل وفهرسة، ونقل واستعلام مع معرّف تتبع فريد `taskId`.
- **متصفح الملفات عن بُعد:** استعراض المجلدات المصرح بها على الجهاز المُدار، البحث، الفرز، ومعاينة الوسائط.
- **مركز النسخ الاحتياطي (Remote Backup):** جدولة وتشغيل النسخ الاحتياطي التفاضلي ومتابعة التقدم والسرعة.
- **سجل التدقيق:** مراقبة العمليات المنفذة، نسبة الإنجاز، والأخطاء.

### ب. دور Clouvea Node (الجهاز المُدار)
- **المصادقة والتسجيل:** تعريف نفسه للجهاز المتحكم بشهادة تشفير فريدة ورمز اقتران ثنائي (Mutual Handshake).
- **حصر الوصول بمجلدات محددة:** استخدام واجهات Android Storage Access Framework (SAF) بحيث لا يتمكن المتحكم من الوصول إلا للمجلدات التي حددها المستخدم صراحة.
- **محرك تنفيذ المهام:** استقبال وتحقق ومعالجة طلبات `LIST_FILES`, `DOWNLOAD_FILE`, `UPLOAD_FILE`, `START_BACKUP` مع دعم الاستئناف بعد انقطاع الاتصال.
- **العمل في الخلفية:** العمل ضمن قيود Android عبر خدمة Foreground Service بإشعار دائم، وجدولة العمليات الطويلة عبر WorkManager.

## 2. التحليل الشامل لكود المشروع المرفق (KDE Connect Analysis)

استناداً إلى الفحص العميق لهيكل ملفات ومستودع `kdeconnect-android-master`:

### ما يمكن إعادة استخدامه بالكامل (Reusable Modules)
1. **نموذج حزم البيانات `NetworkPacket.kt`:** صياغة حزم الرسائل ككائنات JSON أحادية السطر مع قدرة إرفاق تدفقات ثنائية للملفات (`payload`).
2. **طبقة الاتصال المشفرة بالشبكة المحلية (`backends/lan/`):**
   - `LanLinkProvider.kt`: إعلانات UDP على المنفذ 1716 للاكتشاف التلقائي.
   - اتصالات مآخذ TCP/TLS على المنفذ 1716.
   - دعم بروتوكول `mDNS` عبر `MdnsDiscovery.kt`.
3. **نموذج تبادل الشهادات والمصادقة (`PairingHandler.kt` & `SslHelper.kt`):** التحقق من بصمات الشهادات (SHA-256) ومفاتيح RSA لمنع هجمات MITM.
4. **تكامل Storage Access Framework (`plugins/sftp/saf/`):** كود التعامل مع مسارات SAF `DocumentFile` وصلاحيات الشجرة (Tree URI) لقراءة وكتابة المجلدات المقيدة.
5. **مراقبة معلومات الجهاز الأساسية (`Device.kt` & `plugins/battery`):** مراقبة نسبة الشحن، حالة التوصيل، وقوة الإشارة.

### ما ينقصه المشروع الحالي للتحول إلى Clouvea (Gap Analysis)
1. **انعدام فصل الأدوار (No Role Separation):** KDE Connect نظام أقران متماثل (Peer-to-Peer Symmetric) يفترض أن كلا الطرفين يملك نفس الصلاحيات، بينما Clouvea يتطلب دورين متمايزين (Controller آمر، وNode خادم مُدار بصلاحيات محددة).
2. **غياب نظام المهام وحالات التتبع (No Unified Task State Machine):** لا يوجد نظام إدارة طوابير لمهام مثل `LIST_FILES`, `DOWNLOAD_FILE`, `START_BACKUP` مع معرفات فريدة، وحالات استئناف، ونسب تقدم دقيقة.
3. **غياب النسخ الاحتياطي الذكي (No Remote Backup Engine):** لا يوجد محرك للنسخ الاحتياطي التفاضلي، ولا قاعدة بيانات لفحص سلامة الملفات (Checksum / SHA-256)، ولا مقارنة التغييرات قبل الرفع.
4. **اقتصار الاتصال على الشبكة المحلية (Local-Only Limitation):** لا توجد طبقة ترحيل وسيطة (Internet Relay / WebSocket Signaling) للربط بين جهازين عبر شبكات مختلفة (خارج نطاق Wi-Fi المنزلي).
5. **غياب واجهات حصر الصلاحيات الإدارية (No Node Scoped Access Control):** لا توجد لوحة للجهاز المُدار تمكّنه من تفعيل أو تعطيل صلاحيات مجلدات معينة أو استعراض من يتصفح ملفاته في الوقت الفعلي.

## 3. محرك إدارة الملفات عن بُعد (Remote File Management Engine)

```
┌────────────────────────────────────────────────────────────────────────┐
│                  REMOTE FILE MANAGEMENT ARCHITECTURE                   │
└────────────────────────────────────────────────────────────────────────┘

    [ Clouvea Controller ]                         [ Clouvea Node ]
  ┌─────────────────────────┐                   ┌────────────────────────┐
  │ • Remote Explorer UI    │                   │ • SAF Scoped Roots     │
  │ • Sort: Name/Size/Date  │ ── LIST_FILES ──► │   (/DCIM, /Docs only)  │
  │ • Multi-Select Actions  │ ◄── File Tree ─── │ • DocumentFile API     │
  │ • Chunk Stream Receiver │                   │ • MIME Detect & Chunks │
  └───────────┬─────────────┘                   └───────────┬────────────┘
              │                                             │
              ▼                                             ▼
  ┌───────────────────────┐                     ┌────────────────────────┐
  │ DOWNLOAD_FILE (Chunk) │ ── Packet Req ────► │ Stream payload         │
  │ Resume from byte N    │ ◄── Byte stream ─── │ Hash verify (SHA-256)  │
  └───────────────────────┘                     └────────────────────────┘
```

- **استعراض وتصفح المجلدات المشتركة:** يعرض جهاز التحكم أسماء المجلدات المصرح بها فقط.
- **فرز وبحث فوري:** فرز متعدد المعايير (الاسم، الحجم، تاريخ التعديل، النوع) وبحث فوري متقدم داخل النطاقات المصرح بها.
- **التنزيل والرفع المباشر:** نقل الملفات بتقطيع البيانات إلى كتل مجزأة (Chunked Streaming) لدعم استئناف النقل بعد انقطاع الاتصال دون البدء من الصفر.
- **معاينة الصور وتشغيل الوسائط:** توليد صور مصغرة خفيفة (Thumbnails) للمعاينة، وبث تدفقات الوسائط المباشرة.
- **العمليات المتعددة:** تحديد عدة ملفات لتنزيلها أو معالجتها كحزمة مهام واحدة مع إمكانية الإلغاء الفوري.

## 4. محرك النسخ الاحتياطي الذكي (Smart Remote Backup Engine)

```
┌────────────────────────────────────────────────────────────────────────┐
│                   SMART REMOTE BACKUP FLOW ENGINE                      │
└────────────────────────────────────────────────────────────────────────┘

 [Source Folders on Node] ──► [Fingerprint Scanner] ──► [Manifest DB]
   (Selected SAF folders)       (Size + mTime + SHA-256)    (Checksum Registry)
                                                                 │
                                                                 ▼
 [Controller Destination] ◄── [Differential Stream] ◄── [Change Detection]
   (Integrity Verified)         (New/Modified files only)   (Skip unchanged)
```

1. **تحديد مجلدات المصدر وأنواع الملفات:** يتيح للمستخدم تحديد المجلدات وأنواع الامتدادات (مثل: صور، مستندات، مقاطع فيديو).
2. **الفهرسة التفاضلية (Differential Detection):**
   - فحص بيانات الملف (حجم الملف + تاريخ آخر تعديل + بصمة SHA-256).
   - مقارنة السجل المحلي مع قاعدة بيانات النسخ السابقة لتفادي إعادة رفع الملفات التي لم تتغير.
3. **التحقق من سلامة البيانات (Checksum Integrity Verification):**
   - بعد اكتمال نقل كل ملف، يتم توليد SHA-256 ومطابقته مع بصمة المصدر للتأكد من خلوه من أي تلف.
4. **سياسة الاستعادة والأمان:**
   - استعادة النسخة الاحتياطية إلى مجلد يحدده المستخدم.
   - حظر الحذف التلقائي للملفات الأصلية بعد النسخ لضمان سلامة بيانات المستخدم.

## 5. نظام المهام الموحد (Unified Task Engine & Queue)

تعمل كل عملية ككائن مهمة مستقل ذي حالة واضحة:

```typescript
export interface ClouveaTask {
  taskId: string;                    // UUID فريد للمهمة
  sourceDeviceId: string;             // الجهاز المُرسل (المتحكم عادة)
  targetDeviceId: string;             // الجهاز المنفّذ (المُدار)
  type: 
    | 'LIST_FILES' 
    | 'SEARCH_FILES' 
    | 'DOWNLOAD_FILE' 
    | 'UPLOAD_FILE' 
    | 'START_BACKUP' 
    | 'GET_DEVICE_STATUS' 
    | 'SYNC_FOLDER' 
    | 'CANCEL_TASK';
  status: 'pending' | 'executing' | 'completed' | 'failed' | 'cancelled';
  createdAt: number;
  updatedAt: number;
  progress: number;                  // 0 - 100%
  bytesTransferred?: number;
  totalBytes?: number;
  transferSpeed?: string;            // MB/s
  payload: Record<string, any>;
  result?: Record<string, any>;
  errorReason?: string;
  retryCount: number;
}
```

- **قواعد منع التكرار (Idempotency):** معالجة كل `taskId` مرة واحدة فقط لمنع تكرار العمليات الحساسة عند إعادة إرسال الحزم عبر الشبكة.
- **استئناف العمليات:** تسجيل تقدم نقل الكتل البيانية لاستئناف المهام تلقائياً فور عودة الاتصال.

## 6. طبقة الاتصال الهجين (Local & Internet Connectivity)

| الحالة | آلية الاتصال | طريقة العمل |
| :--- | :--- | :--- |
| **الاتصال المحلي (Local LAN/Wi-Fi)** | UDP Broadcast + TCP/TLS Socket | اكتشاف فوري على المنفذ 1716 ونقل مباشر بأقصى سرعة للشبكة المحلية دون استهلاك الإنترنت. |
| **الاتصال عبر الإنترنت (Internet Remote)** | WebSocket + WebRTC DataChannel Relay | خادم وسيط آمن يوجه إشارات الربط، وتوجيه البيانات بنفق P2P أو Relay مشفر طرف-إلى-طرف. |
| **انقطاع الاتصال (Offline Resilience)** | Local Task Queue Storage | الاحتفاظ بالمهام قيد الانتظار وتحديث حالة الجهاز إلى "غير متصل"، مع إعادة المحاولة التلقائية عند الاتصال. |

---

## 7. لوحة معلومات الجهاز والقياسات الرسمية (Device Telemetry)

تعتمد لوحة المعلومات على البيانات الرسمية المتاحة لتطبيقات أندرويد فقط:
- **البطارية والطاقة:** نسبة الشحن، حالة التوصيل بالشاحن (AC / USB / Wireless)، ودرجة الحرارة التقديرية.
- **التخزين المشترك:** مساحة التخزين الإجمالية والمتوفرة في وحدات التخزين المصرح بها.
- **حالة الشبكة:** نوع الاتصال (Wi-Fi 6 / 5G / 4G)، قوة الإشارة بالـ dBm، وزمن استجابة الشبكة (Latency / Ping).
- **حالة خدمة Clouvea Daemon:** جاهزية الخدمة في الخلفية، عدد المهام قيد التنفيذ، ووقت آخر مزامنة ونسخ احتياطي ناجح.

## 8. الأمان والخصوصية وحماية البيانات

1. **مصادقة الحساب والأجهزة:** ربط الأجهزة بحساب المستخدم، وتوليد مفاتيح RSA فريدة لكل جهاز.
2. **الاقتران الصريح برمز PIN / QR:** اشتراط موافقة المستخدم الصريحة على شاشة الهاتف المُدار قبل اعتماد أي جهاز متحكم.
3. **تحديد الصلاحيات ونطاقات SAF:** لا يمكن للمتحكم طلب ملفات خارج المجلدات المحددة عبر Storage Access Framework.
4. **سجل التدقيق (Audit Logging):** تسجيل كل عملية وصول أو تنزيل ملف على الجهاز المُدار مع إظهار إشعار واضح.

## 9. خطة التنفيذ البرمجية المرتبة حسب الأولوية

### المرحلة 1: معمارية النواة ونظام المهام الموحد (Core & Task Engine)
- بناء محرك طابور المهام `ClouveaTaskManager` وحالات العمليات (`pending`, `executing`, `completed`, `failed`).
- تطبيق التبديل التفاعلي بين دور `Clouvea Controller` ودور `Clouvea Node`، مع دعم العرض المزدوج للمحاكاة الفورية.

### المرحلة 2: محرك إدارة الملفات عن بُعد وتكامل SAF
- بناء متصفح الملفات عن بُعد مع محرك فرز وبحث متقدم.
- برمجة نقل الملفات بالكتل المجزأة (Chunk Streaming) ومؤشرات السرعة والتقدم والاستئناف.

### المرحلة 3: محرك النسخ الاحتياطي الذكي (Remote Backup)
- برمجة فاحص التغييرات التفاضلي (Size + mTime + SHA-256 Checksum).
- إنشاء سجل التحقق من سلامة الملفات ومحرك الاستعادة الآمنة.

### المرحلة 4: طبقة الاتصال الهجين ولوحة المعلومات المتقدمة
- دعم التزامن المباشر بين النوافذ والأجهزة عبر قنوات `BroadcastChannel` وخادم WebSockets/P2P.
- تصميم لوحة معلومات الجهاز (البطارية، التخزين، الاتصال، والمهام الجارية).
